SQL Server Bridge

How it works: deploy the sample Node.js + MySQL backend (see documentation below). Point this station at its URL. Every change is written to your SQL database. Firebase is used only as fallback while the SQL backend is offline. Designed for 50+ concurrent users.
Example: https://api.yourschool.edu/best → the station calls /best/sync and /best/health.
Sample Node.js + MySQL backend (copy & deploy) 
// server.js — Node 18+, mysql2, express, cors
//   npm i express cors mysql2
//   TABLE: station_state(station VARCHAR(64), k VARCHAR(64), v JSON, updated_at TIMESTAMP, PRIMARY KEY(station,k))

const express = require('express');
const cors = require('cors');
const mysql = require('mysql2/promise');

const app = express();
app.use(cors());
app.use(express.json({ limit: '8mb' }));

const pool = mysql.createPool({
  host: process.env.DB_HOST || 'localhost',
  user: process.env.DB_USER || 'best',
  password: process.env.DB_PASS || 'best',
  database: process.env.DB_NAME || 'best_station',
  waitForConnections: true,
  connectionLimit: 50,      // ← handles 50+ users
  queueLimit: 0
});

// GET all state for a station
app.get('/best/sync/:station', async (req, res) => {
  const [rows] = await pool.query('SELECT k, v FROM station_state WHERE station=?', [req.params.station]);
  const out = {};
  for (const r of rows) out[r.k] = typeof r.v === 'string' ? JSON.parse(r.v) : r.v;
  res.json(out);
});

// POST one key
app.post('/best/sync/:station', async (req, res) => {
  const { key, value } = req.body;
  if (!key) return res.status(400).json({ error: 'key required' });
  await pool.query(
    'INSERT INTO station_state (station,k,v,updated_at) VALUES (?,?,?,NOW()) ' +
    'ON DUPLICATE KEY UPDATE v=VALUES(v), updated_at=NOW()',
    [req.params.station, key, JSON.stringify(value)]
  );
  res.json({ ok: true });
});

app.get('/best/health', (_req, res) => res.json({ ok: true, ts: Date.now() }));

app.listen(process.env.PORT || 8080, () => console.log('BEST SQL bridge running'));

Domain & HTTPS Lock

What this does: Only allow sign-in when the page is served from one of your approved domains (and optionally only over HTTPS). Anyone else sees a locked screen. This does not replace real server security — combine with HTTPS + firewall for full protection.
Subdomains of a listed domain are also allowed (e.g. listing yourschool.edu allows best.yourschool.edu).
